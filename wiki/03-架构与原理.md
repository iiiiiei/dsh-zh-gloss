# 03 · 架构与原理

本文解释 dsh-l10n-zh 为什么长这样：一切设计都顺着官方机制顺势而为，不做对抗。

## 1. 官方 i18n 机制速览

dsh 的 Web UI 是一套 **Cordis 客户端插件树**：

- 每个客户端包以 `window.__ModuleLoader__.load({ id, factory })` 形式交付 bundle，
  由宿主侧 `@deepseek-ai/dsh-client-modules` 扫描各包 `package.json` 的 `dsh.client`
  声明，编排出启动图并经 `/plugins/<包名>/client.js?rev=<内容哈希>` 下发。
- 浏览器里的 cordis runner（`dsh-cordis-client-runner`）按依赖序物化每个模块，
  把其导出 `{ name, inject, apply }` 当作客户端插件激活；`inject: ["locale"]`
  声明的服务未就绪时插件会**停靠等待**。
- `@deepseek-ai/dsh-client-locale` 提供 `LocaleRuntime`：
  - 字典注册表 `register(ns, { zh, en })`（命名空间 + 语言已存在时**抛错**——
    官方用这个不变量防止覆盖）；
  - 查找链 `translate`: `ns@当前语言 → ns@en → common@当前 → common@en → 键名`；
  - `publish()` 推进 revision 并唤醒所有 useSyncExternalStore 订阅者。

> 关键推论：因为 `register` 会抛错，第三方插件**不可能也不应该**重注册官方字典；
> 因为查找链经过实例方法 `lookup`，一个运行时包裹点就能惠及全部文案。

## 2. 双层翻译设计

```
React 组件 t("trajectory", "toolbar.duration")
        │
        ▼
LocaleRuntime.lookup(ns,key)   ←── 本插件包裹（第一层）
        │  命中 dicts/ui.json[ns][key] 且语言为 zh ?
        │    官方值已含汉字 → 让位（追赶自愈）
        │    否则 → 返回插件词条；未命中 → 透传官方链
        ▼
官方字典值（zh 缺失时回退 en，再回退键名）
        │
        ▼
渲染进 DOM ──→ MutationObserver ──→ 第二层·字面量映射
             （新增/变更文本节点与 title/aria-label/placeholder）
              literals 精确匹配 → chromeLiterals（界面骨架限定）
              → patterns 正则捕获 → 命中则替换并登记原件
```

| 层 | 数据源 | 适用 | 例子 |
|---|---|---|---|
| 一 | `dicts/ui.json` → `ui[ns][key]` | 走 t() 但 zh 值缺失/未译 | trajectory 工具栏 |
| 二·精确 | `dicts/*.json` → `literals[en]` | 硬编码英文、后端下发静态串 | System Prompt、命令释义 |
| 二·chrome | `chromeLiterals[en]` | 通用单词，仅按钮/标题内生效 | Read→读取 |
| 二·模式 | `patterns[]` | 带路径/参数的动态串 | 目录选择宿主报错 |
| 注入 | `pluginInfo[id]` | 插件列表描述（官方不渲染） | include→组合加载 |

第二层为什么安全：

- **整词精确匹配**（折叠空白后全等），不会误伤子串；
- `CODE/PRE/SVG/TEXTAREA/contentEditable` 一律跳过（含 characterData/
  裸文本节点直达路径的父级补查，代码块动态更新不会误译）；
- 官方用户消息气泡（`[data-chat-flow-kind="user"]`）内的文本与属性**永不改写**；
- 每次改写前把 `{original, written}` 登记进 Map——同一节点重复扫描永远以原件为
  基准，**不会叠加翻译**；官方中途改写的值视为新的原件（自动再基准化）；
- 节点从 DOM 移除时随 mutation 记录同步注销（注销前先还原），登记地图不随
  长会话增长；
- 词条被移除时自动回退英文（原件还在）。

## 3. 设置页注入器（开关与插件注释）

一个挂在 `document.body` 上的 MutationObserver（childList+subtree，50ms 去抖），
在设置弹窗出现时驱动两类增强：

- **语言行开关**：用官方 `lookup("settings.locale", "language.title")` 取当前
  语言的「语言」标题文案做锚（跨语言、跨官方改版稳定，不依赖哈希类名），
  把开关插到语言选择药丸的**顶层祖先**之前（官方 Menu 组件会给按钮包一层
  span 容器，直接插按钮前会因父级不匹配抛 NotFoundError）；
- **插件卡片注释**：以「Cordis 状态」（已挂载）或「配置状态」（停用）行为锚，
  用**独占容器判定**向上找卡片——某层恰好包含 1 个词典已知插件名 = 卡片边界；
  ≥2 个 = 已越界（会串台）立即放弃。描述以 dt/dd 对直接插入官方 dl 网格
  （多包一层容器会因网格布局不渲染）。

React 渐进渲染会造成 querySelector 与 insertBefore 之间的竞态——所有插入操作
都有 try/catch + 200ms 重试收敛。

## 4. 热插拔的可逆性保证

1. **安装/卸载走 cordis 生命周期**：补丁层 insert/remove 后由官方 loader 加载/停用；
2. **卸载 = 逆放**：所有副作用都经 `ctx.effect()` 登记 disposer——lookup 包裹
   装回原函数（引用同一性有测试断言）、观察器 disconnect、全部文本/属性
   逐字节还原（仅回写"仍归我们所有"的值，官方中途改写的值不碰）、
   注入的开关/描述行移除、本地词典缓存清除；
3. **词典热更新不走 rev 缓存**：bundle 是代码（极少变动，受官方内容哈希缓存管理），
   词典是数据——宿主半边 `/api/l10n-zh/dicts` **每次请求现读磁盘**
   （`Cache-Control: no-store`），浏览器半边每次页面加载与语言切换时重新拉取。

## 5. 性能与功耗画像

- 无轮询、无 rAF、无 interval；唯一定时器是 30ms 变更去抖，随突变自动归零；
- 全量 DOM 扫描仅发生在首挂载/词典到达/语言切换三个低频事件；
- 每页加载 + 每次切语言各一次词典 fetch；localStorage 缓存消除首屏英闪；
- 拉取失败按 1.5s/4s 退避重试两次即止；
- 三段式查词：全局 literals O(1) → chromeLiterals（词表命中才付 closest 代价）
  → patterns（ASCII 预筛 + 单遍正则）；
- 移除节点即时注销登记，长会话内存不随聊天记录增长；
- 后台标签页：浏览器节流定时器，扫描自动推迟（保证收敛，前台无影响）。

## 6. 与"修改官方源码"方案对比

| 方案 | 升级安全性 | 可逆性 | 维护成本 |
|---|---|---|---|
| 改官方包内文件 | ❌ npx 更新即丢失 | 手工反悔 | 高（散弹式改动） |
| 重打包/patch 官方前端产物 | ❌ 同上 | 差 | 高 |
| **本插件（运行时包裹 + 数据词典）** | ✅ 官方升级最多需要补词条 | ✅ 删条目即还原 | 低（纯 JSON） |
