# 08 · 常见问题（FAQ）

**Q：官方不是自带中文吗，为什么还需要这个插件？**
A：官方有完整的 zh/en 体系，但存在四类漏网：键在而 zh 值没翻（轨迹工具栏）、
硬编码英文不走 t()（标签页标题）、后端下发的数据文案（斜杠命令释义/执行回执）、
官方 UI 压根不渲染的信息（插件描述）。本插件只补这些缺口，官方已翻好的绝不重复处理。

**Q：插件会拖慢 Web UI 吗？**
A：不会。无轮询、无定时循环；页面不动它零动作。全量扫描只发生在首挂载/词典到达/
语言切换三个低频事件，平时只随真实 DOM 变更做 30ms 去抖的增量扫描，
每节点成本是一次 O(1) 字典查找。详见 [03-架构与原理 §5](03-架构与原理.md)。

**Q：为什么 l10n 这个名字？**
A：l10n = localization（本地化）的行业标准缩写（首字母+中间10个字母+尾字母），
zh 是中文的语言代码（ISO 639-1，与官方字典键一致）。含义是"dsh 的中文本地化补全"。

**Q：官方升级后插件会坏吗？**
A：最坏结果是个别文案回到英文，不会白屏或崩溃——一切触点都是"未命中即透传官方链"，
官方契约变更时插件整体惰性降级。追赶成本 = 重跑扫描器 + 补几行 JSON。
见 [05-更新机制](05-更新机制.md)。

**Q：为什么有的英文不翻？（bash / read / TTFT / tok/s / 工作区名）**
A：有意保留。工具名是 agent 实际调用的标识符（翻了会对不上号）；TTFT/tok 是
技术缩写与单位；工作区名和代码内容属于你的数据。想翻工具名说一声即可补。

**Q：「添加工作区」弹出的访达面板为什么还是英文？**
A：那是 macOS 系统原生面板（宿主经 osascript 弹出），面板文案由 macOS 系统语言
决定，任何网页插件都无法触达——这是系统级边界。该流程的错误弹窗英文串已全部覆盖。

**Q：应用内开关和卸载有什么区别？**
A：开关=临时停用（翻译立即还原，词典缓存保留、开关仍在设置页、随时重开）；
卸载=从 cordis 层移除插件本体（连开关一起消失、本地缓存清除、UI 逐字节回官方原状）。

**Q：改了词典要重启吗？**
A：不用。词典每次请求现读磁盘，保存后刷新网页即生效。改 `lib/*.js` 代码才需要
重新打包 + 重启服务器。

**Q：多个浏览器/设备各自要设置开关吗？**
A：是。开关状态存于各浏览器自己的 localStorage，互不同步（词典缓存同理）。

**Q：能翻译日文/其他语言吗？**
A：架构与语言无关（换词典即可），但当前只交付了中文词典。理论上做
`dsh-l10n-ja` 只需替换 `TARGET_LOCALE` 与词典内容。

**Q：会话里的代码块/我打的英文会被改写吗？**
A：不会。CODE/PRE/SVG/TEXTAREA/contentEditable 一律跳过；用户消息气泡
（官方 `data-chat-flow-kind="user"` 标记）有额外硬护栏，整词撞上词条也不改。
