# 05 · 更新机制（官方 dsh 升级之后）

dsh 处于开发者预览期，官方迭代频繁且可能有破坏性变更。本插件的更新策略是：
**最坏结果 = 个别文案回到英文，永远不会是界面损坏**——因为一切触点都是
"未命中即透传官方链"。

## 三道防线

| 防线 | 机制 | 失效表现 |
|---|---|---|
| 装载期 fail-inert | locale/webServer 契约检查，不可用即惰性（不向 cordis 抛错） | 插件不生效，UI 正常 |
| 运行期隔离 | 坏词典按文件隔离、坏正则跳过、锚点找不到静默跳过 | 对应功能缺失，其余正常 |
| 追赶自愈 | 键级命中时回查官方值，官方补出含汉字译文 → 插件让位 | 官方补译零冲突，插件自动收缩 |

## 升级后的标准流程

```bash
# 1. 照常升级并重启 dsh，然后体检：
curl -s localhost:3080/api/l10n-zh/status | python3 -m json.tool
#    关注 officialDshVersion / pluginBaseline / drift 三个字段
```

- `drift: false` 且界面无异常 → 无需任何动作；
- `drift: true` → 官方版本已偏离验证基线，执行第 2 步核对：

```bash
# 2. 重跑缺口扫描（两个参数都可省略）
node tools/scan-locale-gaps.mjs reports/value-gaps.txt
```

- 键级缺口 → 补 `dicts/ui.json`；
- 新的硬编码/后端文案 → 在 DevTools 复制完整原文，补 `literals` 或 `patterns`
  （语法见 [02-使用指南](02-使用指南.md)）；
- 新增插件 → 补 `dicts/30-plugin-info.json`（依据其 package.json 描述）。

```bash
# 3. 重新打包覆盖部署
bash scripts/pack.sh
rm -rf ~/.dsh/profiles/node_modules/dsh-l10n-zh
cp -R dist/dsh-l10n-zh ~/.dsh/profiles/node_modules/
# 重启服务器（核对进程启动时间）→ 刷新网页

# 4. 顺手把 VERIFIED_BASELINE 更新为新版本号（plugin/lib/index.js），
#    下次 drift 检测重新有了基准。
```

## 历史上踩过的坑（对官方升级同样适用）

| 症状 | 根因 | 处置 |
|---|---|---|
| 重启后行为像旧版 | 旧进程未退净占住 3080，新进程 EADDRINUSE 静默退出 | `pkill -f dsh/lib/bin.js` 后重启，核对 `ps` 启动时间 |
| 设置页开关消失 | 官方改了语言行/弹窗结构，锚点找不到 | fail-inert：开关不出现但翻译不受影响；等本仓库适配 |
| 某词突然不翻了 | 官方改了原文文案 | 用 DevTools 取新原文，补一条词条即可 |
| 界面出现异常 | （理论上不应发生） | 卸载插件验证是否与本插件相关，提 issue |

## 词典是纯数据

整套追赶成本 = 重跑一条命令 + 补几行 JSON。词典不含代码、不参与 bundle 构建，
官方任何升级都不需要改插件本体（除非官方改的是 i18n 机制本身——那会被
装载期契约检查捕获并惰性降级，不会白屏）。
