# 04 · 构建与发版

面向本仓库的开发者与贡献者。

## 目录结构

```
├── plugin/                     # 插件本体（交付物源码）
│   ├── package.json            #   dsh.client 声明：platform=web, 注入官方 locale 模块
│   ├── lib/index.js            #   宿主半边：GET /api/l10n-zh/dicts（现读磁盘）+ /status
│   ├── lib/client.js           #   浏览器半边：双层翻译引擎 + 设置页注入器（手写官方 bundle 格式）
│   └── dicts/                  #   词典（热更新区）：ui / literals / 20-trajectory / 30-plugin-info
├── tests/selftest.mjs          # 离线自测：123 项断言（含微型 DOM 桩，确定性驱动）
├── tests/simulation/           # 浏览器真实模拟推演：假宿主 + 真插件 + 真词典
├── tools/scan-locale-gaps.mjs  # 官方包缺口扫描器（键级+值级）
├── scripts/pack.sh             # 打包（语法校验→词典校验→自测→组装）
├── reports/                    # 调研报告存档（值级缺口/访达专项/后端文案）
└── wiki/                       # 本文档
```

## 本地开发循环

```bash
# 1. 改词典（纯数据）→ 部署目录热生效
cp plugin/dicts/*.json ~/.dsh/profiles/node_modules/dsh-l10n-zh/dicts/
#    刷新网页即生效，无需重启

# 2. 改代码（lib/*.js）→ 需要重新打包部署
bash scripts/pack.sh
rm -rf ~/.dsh/profiles/node_modules/dsh-l10n-zh
cp -R dist/dsh-l10n-zh ~/.dsh/profiles/node_modules/
#    重启服务器（并核对进程启动时间！）→ 刷新网页
```

## 调试探针

浏览器控制台执行 `localStorage.setItem("dsh-l10n-zh:debug","1")` 后刷新，
注入器执行轨迹会写入 `window.__l10nDebug`（上限 80 条）。排查设置页开关/
插件注释问题首选。

## 版本与发版

版本号规则：`0.<功能>.<修复>`（功能位在新能力落地时 +1）。发版流程：

1. 更新 `plugin/package.json` 版本号与 `wiki/09-版本历史.md`；
2. `bash scripts/pack.sh` 产出 `dist/dsh-l10n-zh-<版本>.tar.gz`；
3. git tag + GitHub Release 附上 tar.gz；
4. 官方 dsh 升级后：重跑扫描器核对缺口，必要时同步更新
   `plugin/lib/index.js` 里的 `VERIFIED_BASELINE`。

## 词典维护约定

- 文件名序即合并序（`10-` `20-` `30-` 前缀控制层叠，后读覆盖先读）；
- 带动态部分的串一律进 `patterns`（正则锚定首尾，`$1~$9` 引用捕获组），
  避免误伤同前缀的其他文案；
- 通用单词（Read/Write/Edit/Search/Code/Fetch/Inspect）只进 `chromeLiterals`；
- 翻译依据：官方包源码 / `package.json` 原文，不凭空造词；
  产品专名（Cordis、Full access 场景下官方保留的英文术语）保持官方风格。
