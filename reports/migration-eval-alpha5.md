# 迁移路线评估 · 自研词典 → 官方 locale 机制

> 2026-09-03 · 基于 0.1.2-alpha.5 实测源码。结论先行：**不建议整体迁移，建议"守字面量、交还键级"**。

## 1. 官方多语言框架的现状（alpha.5 实测）

- 官方 zh/en 词典覆盖持续扩张：a2 起内置多语言框架；a5 里连轨迹 KIND_LABEL
  都已 i18n 化（`KIND_LABEL_KEY` → `kind.*` 键，zh 完整：助手/上下文/子工具/已压缩…）；
- a5 键级缺口仅剩 31 条（`reports/value-gaps-alpha5.txt`），且大多是
  **有意保留英文**的（JSON/px/tok/K/M 单位、Tab 键名、my-agent 占位示例、
  Plan/Skill 徽章专名）——真正该翻的极少；
- 新增 UI（模型目录向导、子智能体面板、权限标签新措辞、侧栏改版）官方 zh
  基本同步交付。

## 2. 两个机制的关系正在从"互补"走向"收编"

| 层 | 本插件手段 | 官方动向 | 收编状态 |
|---|---|---|---|
| 键级覆盖 | `ui[ns][key]` 覆盖表 | 官方 zh 字典持续补齐 + 补译让位机制 | **接近完成**——a5 键级缺口基本是有意保留项 |
| 字面量层 | literals/chromeLiterals/patterns | 官方不打算管"不走 t() 的遗留裸串"（若有） | **仍是本插件独有价值** |
| 注入层 | pluginInfo 插件注释（官方不渲染描述） | 无动向 | **独有功能** |
| 开关 | 应用内开关 | 无对应物 | 独有功能 |

## 3. 为什么不建议整体迁移到官方机制

1. **官方没有"第三方补词"入口**：`LocaleRuntime.register()` 遇重复命名空间抛错，
   第三方无法向官方字典追加词条。迁移 = 放弃我们全部词条，退回"官方翻什么看什么"；
2. **字面量层没有官方对应物**：不走 t() 的硬编码文案、后端下发的数据文案，
   官方 i18n 机制管不到。a5 实测仍有残留（模型目录向导、子智能体、作用域说明
   等 50+ 条裸串，已由本轮补录收编）；
3. **迁移成本 > 维护成本**：词典是纯 JSON，官方补译时键级词条经"让位机制"自动
   失效——**键级层的维护成本已被机制归零**，没有迁移收益。

## 4. 建议的长期路线（收缩而非迁移）

1. **键级层持续收缩**：官方补译 → 让位机制自动生效 → 词条沦为死重。每次官方
   升级跑扫描器时，顺手删掉已让位的词条，保持词典最小；
2. **字面量层维持**：每版官方更新后重跑字面量静态扫描（本次的方法已可复现），
   新 UI 裸串逐条收录；官方若把某串 i18n 化，删除对应词条即可；
3. **观察官方态度**：若官方未来提供"社区词典贡献"机制或字面量 i18n 化路线图，
   再评估整体退役。触发信号：官方 zh 覆盖连续两个版本零新增缺口；
4. **pluginInfo 注入是长期功能**：官方不渲染插件描述是产品决策而非疏漏，
   本插件的注入与官方路线无冲突。

## 5. 对 v0.1.2-rc.1 的评估

发布说明与 a5 同支（handoff 判定"区别不大"），当前已按 a5 实测完成适配。
升级 rc.1 时按标准流程：`/status` 看 drift → 重跑扫描器 → 补词条。
本插件的 `VERIFIED_BASELINE` 现为 `0.1.2-alpha.5`，rc.1 上线后会正确显示
`drift: true` 提示核对。
