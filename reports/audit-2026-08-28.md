## 发现与建议

### P1-1 · originalAttrs 无条件登记 → 内存持续增长（`client.js:210`）

`translateElementAttrs` 在判断命中**之前**就把元素塞进 `originalAttrs` Map：只要元素带有 title/aria-label/placeholder/aria-description 之一（无论是否翻译），都会永久登记一条。且 `onMutations` 不处理 `removedNodes`，已移除节点的登记永不清理——长会话下随 DOM 流转持续增长。

**修法**：登记移入命中分支；`onMutations` 遍历 `removedNodes` 对两张 Map 做 `delete`。

### P1-2 · 裸文本节点直达路径绕过 SKIP_TAGS / contentEditable（`client.js:226`）

`characterData` 变更与 `addedNodes` 中的裸文本节点直接进 `translateTextNode`，不查父级跳过规则（元素根路径有检查，文本根路径没有）。后果：代码块内文本更新、或 contentEditable 编辑器里用户输入恰好整词命中词条（如 "Options"、"Tools"）时会被误改写。自测只覆盖元素根路径，此旁路无测试断言。

**修法**：`translateTextNode` 前置父级检查（祖先命中 SKIP_TAGS 或 isContentEditable 即返回）。

### P1-3 · 维护闭环断裂：扫描器空参崩溃 + wiki 教的命令错误（`tools/scan-locale-gaps.mjs:17`）

`process.argv[2] ?? 默认值` —— `??` 不拦空字符串。而 `wiki/02` §5 教的正是 `node tools/scan-locale-gaps.mjs "" reports/value-gaps.txt`，**必然 ENOENT 崩溃**。官方升级后的第一动作就报错。无参运行正常（默认路径生效）。

**修法**：改为 `process.argv[2] || 默认值`，同步修正 wiki 命令；补一条"空参也能跑"的用法说明。

### P2-4 · pack.sh 盲区：不校验 10-backend-copy.json；tar 混入 .DS_Store

`pack.sh:13-25` 只校验 `ui.json` 和 `literals.json`——`10-backend-copy.json`（含 patterns + chromeLiterals）的语法错误会照常打包上线（运行时有按文件隔离兜底，但打包本应拦截）。`cp -R` 把 `plugin/.DS_Store` 带进了产物与 tar。

**修法**：校验循环覆盖全部 `dicts/*.json`；打包前 `find … -name .DS_Store -delete` 或拷贝时排除。

### P2-5 · 宿主半边 register 无护栏（`lib/index.js:111,126`）

客户端半边处处 fail-inert，但宿主 `ctx.webServer.register(...)` 裸调：官方若改 webServer 服务契约，apply 直接抛错（cordis 反复报错）而不是惰性降级。

**修法**：两处 register 各包 try/catch，失败仅 `logger.warn` 并保持插件惰性。

### P2-6 · 词典拉取失败无重试（`client.js:95-111`）

一次 fetch 失败（服务器重启瞬间、弱网首载）即静默保持英文，直到下次手动刷新或切语言。与"轻量"目标完全不冲突的高价值韧性：**失败后退避重试 1–2 次即止**（不引入常驻轮询）。

### P2-7 · originalTexts 同样缺 removedNodes 清理

与 P1-1 同根，同一次修复覆盖。

### P3 · 可选优化（按需）

| 项 | 说明 | 收益 |
|---|---|---|
| inChrome 惰性求值 | 当前每个文本节点都先跑 `closest()`（`client.js:182`），即使全局 literals 已命中/必然未命中 | 每节点省一次祖先链遍历 |
| patterns 单遍 + 预筛 | `re.test` + `replace` 双跑正则；循环前加 `/[A-Za-z]/` 预筛（pattern 源串全为英文） | 未命中节点从 ≤13 次正则降为 1 次 ASCII 判断 |
| applying 标志明示无效 | MO 回调是微任务，执行时 `applying` 已归零——抑制从未生效，靠幂等收敛兜底（无害）。改注释明示，防后人误依赖 | 可维护性 |
| 首屏英闪 | 词典异步到达前 t() 输出英文；可选 localStorage 缓存上一版词典做 stale-while-revalidate | 首屏体验 |
| /status 版本回声 | 宿主启动时读官方 dsh 版本 + 插件基线 `0.1.1-rc.2` 一并返回 | 漂移一眼可见，零运行时成本 |
| 键级"官方补译即让位" | 命中自有词条时回查官方结果，含汉字（`/[\u4e00-\u9fff]/`）即让位 | 官方补齐的翻译自动生效，插件自我收缩 |

## 应对官方更新的韧性策略（分层模型）

| 层 | 机制 | 现状 |
|---|---|---|
| L0 装载期 fail-inert | 契约检查，服务不可用即惰性 | 客户端✓ / 宿主△（P2-5） |
| L1 运行期隔离 | 词典按文件隔离、坏正则跳过、en 模式零行为 | ✓ |
| L2 追赶自愈 | 官方补译后插件自动让位 | 建议（P3 末项） |
| L3 漂移检测 | 版本回声 + 扫描器 | △（P1-3 修复 + 建议：扫描器只覆盖键/值级，**pattern 层的宿主英文串没有自动检测工具**——那是子代理人工调研成果，建议为字面量层补一个"官方 bundle 英文串 ↔ 词典键"差分脚本） |
| L4 兜底 | 卸载逐字节还原 | ✓（测试覆盖） |

**核心设计判断**：官方任何升级的最坏结果 = 个别文案回到英文（**永远不会是界面损坏**）——因为一切触点都是"未命中即透传官方链"。追赶成本 = 重跑扫描器 + 补纯 JSON 词条，无需动代码。

## 功耗与轻量化画像

- 无轮询、无 rAF、无 interval；唯一定时器是 30ms 变更去抖，随突变自动归零
- 每页加载 + 每次切语言各一次词典 fetch（no-store）；全量 body 扫描仅发生在首挂载/词典到达/语言切换三个低频事件
- 每文本节点成本：norm + literals O(1) 查找 + （急切的）closest + ≤13 条正则 test——P3 两项可再压
- **明确不建议**：开启 `attributes: true` 观察（回调量激增，当前取舍正确，应作为"已知取舍"写进 wiki）；轮询式词典检查；IntersectionObserver 门控；shadow DOM 支持（官方未使用）

**优先级**：P1 ×3 + P2 ×4 都建议修（全部是局部改动，不引入新机制、不增加常驻开销）；P3 按需，其中"/status 版本回声"与"官方补译让位"对官方升级应对最有杠杆。
